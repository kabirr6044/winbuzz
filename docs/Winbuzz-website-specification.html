Implementation and validation requirements

Use npm install, copy .env.example to .env.local, set EXTERNAL_REDIRECT_URL, and run npm run dev. Production commands are npm run build and npm start. The application uses Next.js 16 with React 19 and the App Router. Server rendering reads the captured local page data; React handles menu, FAQ coordination, forms, score tabs, and review navigation. Unknown routes return a local 404 page. No WordPress hosting is required.

Run npm run audit to validate internal link coverage, image locality, external-link routing, tracker removal, and form privacy. With AUDIT_BASE_URL set to the preview origin, the audit additionally checks every route returns HTTP 200, the /out GET and POST responses redirect with status 303, and a missing route returns 404. Review desktop and mobile layouts, menu opening and closing, hash navigation, FAQ expansion, article pagination, form redirects, and local asset loading before assignment submission.

Responsive browser verification

All 271 captured routes were tested in the browser at widths of 320, 375, 425, 768, 1024, 1280, 1440, and 1920 pixels, for 2168 responsive checks. No horizontal overflow, broken eagerly loaded images, or remote image references were found. Sixteen source layouts were compared at those widths for static text geometry, typography, colors, and corners, with no remaining measured differences after correcting utility corner radii and testimonial spacing. This is a template comparison plus a complete route sweep, rather than a pixel comparison of every full page. Direct viewport comparison with the third-party score provider was blocked by browser permission; its downloaded styles and local implementation were tested separately. Evidence and screenshots are retained in docs/visual-qa.
