Technical audit and acceptance checks

P0Global indexing block

Evidence: Confirmed in repository; verify live response in HTTP evidence

Finding: app/layout.js sets robots index:false and follow:false. All captured pages inherit this.

Required change: For a legitimate original production information site, use route-specific index/follow for approved pages. Keep assignment demos and thin/utility pages noindex. Do not switch on indexing before copy and affiliation are accurate.

Acceptance check: Fetch normal and Googlebot responses; approved routes must have neither meta noindex nor X-Robots-Tag noindex. Confirm with Search Console URL Inspection.

PASSServer-rendered page architecture

Evidence: Confirmed by code; raw HTML checked where available

Finding: The catch-all page is an async Server Component. Replica is a Client Component but its dangerous HTML is pre-rendered on an initial request; use client does not itself imply client-only content.

Required change: Keep meaningful headings, text and anchors in initial HTML. SSR does not need to be added from scratch.

Acceptance check: Raw HTML should contain the H1, body text and internal hrefs without executing browser JavaScript. SSR/SSG alone does not guarantee rankings.

P1Public sitemap missing

Evidence: Confirmed: no app/public sitemap route

Finding: reference/sitemap.xml is a capture of the source site, not a served sitemap for our host.

Required change: Add app/sitemap.js based on approved, canonical, indexable routes. Use the canonical origin defined in lib/seo.mjs for the chosen production domain; omit noindex archives, redirects, /out, /scores, APIs and specification.html. Use genuine modification dates, not the current deploy time for all pages.

Acceptance check: GET /sitemap.xml must return 200 XML with only our production hostname; validate URL status, canonical and robots alignment; submit in Search Console.

P1robots.txt absent

Evidence: Confirmed: no app/robots.js or public/robots.txt

Finding: No explicit crawl policy or sitemap declaration exists. Its absence alone does not prevent crawling.

Required change: Add app/robots.js and a sitemap URL for the chosen production domain. Avoid blocking public pages that need Google to see noindex. robots.txt is not an access-control mechanism.

Acceptance check: GET /robots.txt returns the intended policy and the correct absolute sitemap URL.

P1Canonical host and URLs absent

Evidence: Confirmed: generateMetadata returns only title and description

Finding: No metadataBase or alternates.canonical configured; custom domain remains unknown.

Required change: Set the canonical origin in lib/seo.mjs to the preferred HTTPS custom domain. Emit a self-canonical for each retained page, including distinct pagination. Configure alternate www and Render hostname redirects or indexing controls appropriately. Never point canonicals to officialwinbuzz.com for content intended to rank independently.

Acceptance check: Inspect canonical in returned head; ensure it is a 200 indexable URL on the chosen host; check HTTP/www/Render aliases separately.

P1Copied content and redirect-only experience

Evidence: Confirmed in capture architecture and /out handler

Finding: Content mirrors an unrelated source; simulated forms do not authenticate or create accounts.

Required change: Original research, accurate publisher disclosure and functionality-aligned copy must precede indexability. Redirect-only pages need independent user value and clear destination labels.

Acceptance check: Review every approved page for original value, affiliation accuracy and unsupported claims; do not promise OTP/account services that this site cannot perform.

P1Duplicate articles and taxonomy

Evidence: Measured in local capture audit

Finding: Eight article pairs have identical extracted main text; other identical groups are archives. Shared headings alone are not an identity test.

Required change: Review full pages and performance before consolidation. Use 301/308 only for approved replacements; update internal links and sitemap. Keep uncurated tag pages noindex, follow.

Acceptance check: No redirect loops/chains; retained pages cover distinct intents; canonical and sitemap agree.

P2Descriptions and titles

Evidence: Measured in local capture audit

Finding: 166 captured pages have no description; 9 title groups repeat. All 271 have one H1, but archives use a generic blog heading.

Required change: Use page-specific titles/H1s and descriptive summaries on selected pages. Descriptions influence snippets rather than being a direct ranking boost; Google can rewrite them. Do not optimize every thin archive for search.

Acceptance check: Check rendered metadata for each approved route and uniqueness of retained titles; descriptions must honestly summarize content.

P2Images and page performance

Evidence: Live raw response and source inspection; CWV not measured

Finding: The homepage response is 744,287 bytes after decompression. Captured HTML and styles are also sent to a client component as props, and captured image markup is preserved. Large inline payloads and images warrant measurement.

Required change: Measure representative mobile pages in PageSpeed Insights. Optimize large hero assets and responsive image sizes, reserve image dimensions and reduce repeated inline CSS/client props where safe. Avoid lazy loading the LCP hero. Consider SSG only after measuring; current SSR can be sufficient.

Acceptance check: Use field data when available: LCP <=2.5s, INP <=200ms, CLS <=0.1 at the 75th percentile. A single lab test or cold Render response is not a field CWV assessment.

P2Structured data and social metadata

Evidence: Confirmed in local source

Finding: Capture strips scripts and root metadata has icons but no explicit Article/Breadcrumb JSON-LD or social metadata.

Required change: Add Article and BreadcrumbList only on eligible, accurate pages, with true author and dates; add OG/Twitter metadata for sharing. Do not invent review ratings or expect FAQ schema to guarantee rich results.

Acceptance check: Validate schema against visible content. These are discovery/presentation improvements, not automatic ranking boosts.

P2Utility routes and index hygiene

Evidence: Repository inspection

Finding: /scores is an iframe utility; /out is a 303 destination; APIs and specification.html are not search landing pages.

Required change: Maintain noindex on utility HTML and use X-Robots-Tag where appropriate for non-page endpoints. Keep these out of sitemaps. Keep true 404 responses for nonexistent pages; do not redirect all 404s to home.

Acceptance check: Check /out returns 303 to configured destination and missing pages return 404; ensure new indexing changes do not expose utilities.

P1External destination remains a placeholder

Evidence: Confirmed live GET /out

Finding: The deployed redirect returns 303 to https://your-destination.com/. This is a configuration placeholder rather than a useful destination.

Required change: Set EXTERNAL_REDIRECT_URL in Render to the intended complete HTTPS URL, redeploy as needed and label the external destination accurately on the site. This report does not choose a destination on the publisher’s behalf.

Acceptance check: Check GET and POST /out return the intended destination and do not include form data. Confirm destination availability and matching button labels.

P1Search Console and deployment validation

Required change: Verify the chosen domain property in Search Console, inspect primary pages, submit sitemap and monitor indexing and query/page performance separately for India/mobile and desktop.

Implementation order

  1. Confirm publisher identity and the preferred custom domain; rewrite the homepage, login/signup explanations, contact and policies accurately.
  2. Select content owners for login troubleshooting, recovery, deposits and withdrawals. Review eight identical article pairs and overlapping guides before redirecting anything.
  3. Add domain-aware canonical metadata, route-level indexing controls, robots.txt and a sitemap containing only approved pages. Keep demo utilities and uncurated archives noindex.
  4. Deploy and verify raw HTML, robots, canonical, sitemap URLs, 404s and approved redirects. Inspect the deployed pages with Search Console.
  5. Improve priority guides with first-hand evidence, specific examples, author information and contextual internal links. Measure mobile performance before choosing optimization work.
  6. Compare 28-day Search Console periods by query/page and country/device; prioritize relevant pages receiving impressions around positions 5–20. New-site improvements are not guaranteed within a fixed time.
